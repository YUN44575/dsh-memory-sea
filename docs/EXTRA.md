# 附加数据源（可选）

主 README 讲的是一条最小链路：**DSH 会话 → 星图 + 给 AI 的记忆工具**。
这一页讲**额外还能接进来的东西**——每一个都是可选的：

- 没有对应的数据 → 管线跳过它，星图照常工作，只是少一块
- `node sea-build/doctor.mjs` 会列出「有哪些、缺哪些」

---

## 1. 长期记忆（`fish-memory`）

**路径**：`<DSH>/.dsh/fish-memory/*.json`

这是 DSH 的 fish-memory 插件存下来的「记忆条目」：一句话一条，带重要性、情绪、标签、
以及「已被取代」的标记（旧版本会被它自己清理）。

接进来之后：

- 星图上多一类来源 `fish-memory`（默认开启，可以在「来源」里关掉）
- `sea_recall` 会一起查这些条目
- 体检页里它们和普通对话一样参与重复 / 忘没忘的统计

**为什么值得接**：会话记的是「说过什么」，记忆条目记的是「提炼出来的结论」。
搜一个词时，两边都能命中，比只翻原话省事。

---

## 2. 世界日记（`worlds`）

**路径**：`<DSH>/.dsh/worlds/default/diary/*.md`、`worlds/default/conversations/*.jsonl`

如果你装了 dsh-world 这类「有自己生活的角色」插件，它会自己写日记、也会把跟你的对话记一笔。

接进来之后：

- 日记按段落切成星星，来源是 `world-diary`，自动进**陪伴海**
- 对话记录（`conversations/*.jsonl`）**不会重复上星**——它们本身就是从 DSH 会话抽出来的副本。
  我们只做一件事：给对应的原话打一个标记，详情里多一行
  「**这件事世界那边也记了一笔 · 2026.10.29 19:21**」
- 体检页里会多一格「世界也记了一笔」

**为什么值得接**：同一件事有两个视角——你记得的，和它记的。两边对不上时，那正是有意思的地方。

---

## 3. SurfCore 记忆卡（可选插件）

**路径**：`<DSH>/.dsh/surfcore/characters`

SurfCore 存的是「衰减中的记忆卡」：每条有清晰度（还很清楚 / 开始模糊）、重要级、是否置顶、
以及「忘了」的记录。它和自己的一套遗忘曲线配合，跟普通聊天不是一回事。

接进来之后：

- 页面上多一个数据源（左上角 `SurfCore 记忆` 切换），是**另外一片海**
- AI 多一个工具 `sea_surf`（参数 `q` / `kind` / `state` / `limit`）
- **没装 SurfCore 就不会挂这个工具**——能力探测在插件启动时做一次，缺了直接不注册，
  不会给你一个永远报错的工具

**注意**：这本子只读不写。想让 AI 往 SurfCore 里写，得等它自己开放接口——
直接改它的 `memory-card.json` 会绕过去重、配额和归档逻辑，早晚打架。

---

## 4. 团队协作（子代理 / Team）

这个**不是**外部数据源，是 DSH 会话本身的一部分：
`source.kind === 'agent-message'` 的消息（Lead 和子代理之间来回的那些）。

默认就接，来源里显示为 `团队协作`。

**为什么单独提**：这类消息在普通会话视图里基本看不到（它们不是「你说的话」也不是「我的回复」），
但在星图上它们会作为独立的星出现——排查时经常是这里最有信息量。

---

## 怎么确认接上了

```bash
node sea-build/doctor.mjs
```

它会逐个检查：

```
数据源
  ✓ DSH 会话目录   C:\Users\you\.dsh\sessions        42 个会话归档
  ✓ 附件           ...                                71 张缩略图
  ✓ fish-memory    ...                                16 条记忆
  ✓ 世界日记       ...                                75 段
  - surfcore       （没有，跳过）
```

没有的那几行显示 `-`，不影响其他部分。

## 想调整分域（工作海 / 陪伴海）

改 `sea-build/domains.json`，然后 `node sea-build/setup.mjs` 重跑。规则按优先级：

1. `overrides` —— 点名某个会话（写 8 位短 id 或 `短id@标题片段`）
2. `byWorkspaceTitle` —— 按 DSH 工作区标题（比如「鲸鲸的房间」→ 陪伴海）
3. `byTitlePrefix` —— 按会话标题前缀
4. `byCwdContains` —— 按目录片段（比如路径里有 `.dsh\worlds\` → 陪伴海）
5. `default` —— 剩下的默认归工作海

**粒度是「会话」不是「话题」**：一个会话里既聊工作又聊生活，它只会被分到一边。
按话题分会失真，得不偿失。
